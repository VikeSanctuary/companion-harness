# Memory Patterns

Memory is necessary, but memory is not the whole system.

## Why Raw Memory Dumps Fail

Dropping a large archive into context can cause:

- Irrelevant recall
- Tone drift
- Contradictory facts
- Old mistakes resurfacing
- Important corrections getting buried
- The model sounding like a summary instead of a companion

The goal is not maximum memory. The goal is useful continuity.

## Better Pattern: Anchors Plus Retrieval

Use a small set of stable anchors, then retrieve only what the moment needs.

Stable anchors may include:

- Name
- Relationship
- Current projects
- Standing boundaries
- Recent open loops
- Known tone preferences

Retrieved memories may include:

- Last session summary
- Relevant corrections
- Related decisions
- Project-specific logs
- Emotional context when appropriate

## Memory Types

### Identity Memory

Who the companion is in this relationship.

### Relationship Memory

Who the human is, what the relationship means, and how they communicate.

### Project Memory

What is being built, changed, debugged, or planned.

### Correction Memory

Mistakes, repairs, preferences, and lessons that should persist.

### Boundary Memory

What must not be shared, changed, automated, or assumed.

### Receipt Memory

What happened, when, why, and what remains open.

## Retrieval Rule

Retrieve the smallest set of memories that can honestly orient the companion for the current task.

Too little context causes amnesia. Too much context causes fog.
